# Bank Marketing Classification Model

## a. Problem statement

Predict whether a client subscribed to a term deposit (`y = yes`) after a bank marketing campaign. This project trains five classification models once, compares them on a fixed stratified holdout set, and provides a Streamlit app for evaluating new labeled test CSVs without retraining.

## b. Dataset description

The [UCI Bank Marketing dataset](https://archive.ics.uci.edu/dataset/222/bank+marketing) contains 45,211 instances, 16 input features, and a binary target (`yes`/`no`). The input columns include client, campaign, and contact attributes; categorical and numeric features are preprocessed in each saved model pipeline. The target is imbalanced, so precision, recall, F1, MCC, and AUC are reported alongside accuracy.

The training script downloads the official UCI archive and creates a reproducible 80/20 stratified train/test split using random state 42. The held-out 20% is included as `test_data.csv` for the app and evaluation.

### Model performance observations

The positive `yes` class is a minority, so accuracy alone can be misleading. A model that identifies more actual subscribers may also produce more false positives, lowering precision while increasing recall. For that reason, the comparison considers positive-class precision, recall, F1, MCC, and AUC alongside accuracy.

The Support Vector Machine in this experiment is `LinearSVC` with balanced class weights, not a tuned nonlinear-kernel SVM. Logistic Regression is also a linear classifier, and both models use the same scaled numeric and one-hot encoded categorical features. Their similar results are therefore plausible: on this representation and with these fixed settings, neither model clearly dominates. SVM has a slightly higher F1 (0.5582 vs. 0.5527) and MCC (0.5136 vs. 0.5092), while Logistic Regression has a marginally higher AUC (0.9079 vs. 0.9077). These small differences do not establish that one algorithm is generally better.

These metrics come from one reproducible stratified 80/20 holdout split, with no hyperparameter search. They describe the models on this test split and configuration; cross-validation and tuning would be needed to make a more robust comparison. The dataset itself is not a problem just because SVM does not win every metric.

## Project files

- `app.py`: Streamlit interface for model selection, CSV upload, evaluation metrics, confusion matrices, and classification reports.
- `train_models.py`: Downloads the UCI data, creates the fixed split, trains the models, saves pipeline files, and prints comparison metrics.
- `modeling.py`: Shared model, preprocessing, and metric definitions.
- `models/`: Five saved preprocessing-and-classifier pipelines used by the app.
- `test_data.csv`: Labeled stratified holdout sample with the required 16 features and target column.
- `requirements.txt`: Runtime dependencies.

## Run locally

```bash
python -m pip install -r requirements.txt
python train_models.py
streamlit run app.py
```

The app loads the included `test_data.csv` when no file is uploaded. To evaluate another dataset, upload a labeled CSV containing the same 16 feature columns and a `y` column containing `yes` or `no`. The app never fits or updates a model from uploaded data.
